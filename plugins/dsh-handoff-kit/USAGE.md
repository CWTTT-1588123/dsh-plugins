# dsh-handoff-kit 使用说明：标准交接流程

<!-- docs-meta: status=current; phase=P2; verified=2430f1b@2026-10-23; tracks=-; supersedes=-; superseded-by=- -->

> 面向用户的**操作顺序**（插件 ≥0.3.1）。UI 入口：对话输入框左侧「交接」按钮。
> 核心原则：**交接包只提供上下文，不是立即开工的许可。**
> 一句话：**旧会话生成 → 新会话粘贴 → 旁证复核 → 新会话收到明确指令后再开工。**

## 1. 标准四步

### 第 1 步（旧会话）：生成并复制开场提示词

1. 点输入框左侧「交接」→「生成」Tab；
2. 标题、备注可选（备注会写进 HANDOFF 的 H1）；目标默认 `user`；
3. 点 **「生成并复制开场提示词」**；
4. 等绿色结果卡片，确认 **batchId、真实目录、warnings**，无错误码。

> 写操作只由这次显式点击触发；点击前 UI 显示目标根目录，不会自动写盘。

### 第 2 步（新会话）：只粘贴提示词，不加任何话

1. **新会话必须使用同一个工作区**：哪个工作区生成的交接包，就在哪个工作区的新会话里粘贴。
   （`handoff_load` 按当前会话的项目 key 查找批次；贴到别的项目会报 `HANDOFF_BATCH_NOT_FOUND`。）
2. 把第 1 步复制到的**整段开场提示词**粘贴发送，**不要再补**"别写文件""先只读"之类的保险句——
   提示词本身已内置强制边界与只读验证步骤。
3. 预期表现：新会话先 `handoff_load` 复核 → `trust=verified` → 按 H2 → H3 → H4 → H8 只读阅读
   → 汇报 trust / 覆盖缺口 / 建议的下一步 → **停下来等你的明确指令**。

### 第 3 步（旁证复核，推荐，约 10 秒）

在旧会话（或另一个有仓库访问权的会话）做**只读**核对，独立确认新会话没有越界写入：

- `git status --porcelain` 输出为空（工作树相对 HEAD 干净）；
- 交接包哈希仍 `verified`（artifacts / 源文件 / gitHead 一致）；
- 批次数与生成时一致，没有新增批次或新文件。

> 单人使用可替代：让新会话贴出 `git --no-optional-locks status --porcelain` 的输出。
> 目的：不轻信"我没写文件"的自报，用独立事实核对。

### 第 4 步（新会话）：收到明确指令后再开始工作

- 新会话必须等你发出**明确指令**后才可修改/创建/删除文件、commit 或开始下一阶段；
- 旧会话此时可以退休（交接完成）；
- 写操作仍须显式确认（与平时 DSH 写操作一致）。

## 2. 不要做的事

| 不要 | 原因 |
|---|---|
| 在别的项目工作区粘贴本项目的提示词 | `handoff_load` 按当前项目 key 查找 → `HANDOFF_BATCH_NOT_FOUND` |
| 在新会话补"保险句" | 0.3.1 起提示词自包含；补话等于给提示词打补丁，掩盖真实缺陷 |
| 忽略 `trust=stale/invalid` 继续工作 | stale 有漂移/警告，invalid 不可信；先看 findings 再决定 |
| 生成后立刻改仓库文档，还期待包保持 verified | 包记录 `docs/` 等的哈希，任何被记录文件变化都会转 stale（正确漂移） |
| 让新会话"直接接着干"而不先只读验证 | 这正是 0.3.0 越界风险的来源；0.3.1 已在提示词里禁止 |

## 3. 常见问题

- **新会话报 `trust=stale`**：生成后工作区（含 `docs/`）有文件变化，或包本身有 warning。
  看「载入」Tab 的 findings；确认无碍后可继续，或重新生成一枚新包。
- **H2 概念词典 / H5 流程显示"未提供"**：生成时没有提供 `concepts` / `flow` 等输入，
  属**输入缺口**（生成器不编造），不是包损坏。
- **找不到批次（`HANDOFF_BATCH_NOT_FOUND`）**：新会话工作区不是交接包所属项目；
  或包在 `target=workspace` 而非 `user`。
- **界面语言不对 / 想切回中文**：界面默认跟随浏览器语言（中文浏览器显示中文）；也可在工作台
  「项目/会话」栏或浮层面板顶部的 **中文 / English** 按钮手动切换，选择会记在本地
  （`dsh.handoff-kit.locale`）。
- **添加/更换 git remote 后看不到旧批次**：项目 key 会变；工作台会以「历史项目（只读）」分组
  显示同工作区名（slug）的历史 key 批次（无关项目不会混入），显式 `handoff_load batchId=...`
  也会只读回退并给出 `PROJECT_KEY_FALLBACK` 警告；写操作仍只写当前 key。
- **同一批次再验变 stale**：只要被记录的仓库文件变过就会出现；这是正确的漂移检测。
