# ADR-0003：交接产品回归 prompt-first，并以 UI 工作台作为 P2 首块

<!-- docs-meta: status=frozen; phase=cross; verified=ca27745@2026-10-22; tracks=-; supersedes=-; superseded-by=- -->

- 日期：2026-10-22
- 状态：**已接受**
- 相关：[WORKSTREAMS](../WORKSTREAMS.md)、[ADR-0001](0001-handoff-kit-repo-and-decisions.md)、[ADR-0002](0002-document-governance.md)、[P2 计划](../handoff-kit/design/P2_plan.md)、[用户原意（v1，已归档）](../archive/handoff-kit/20261022_通用交接包生成器_v1.md)

## 背景

1. 用户最初的需求是 **prompt-first**：一段通用交接提示词 → 当前工作区生成"给下一个工作区的对接提示词" → 下一个工作区照做。原意保存在 v1 文档（已归档）。
2. P0/P1 把这件事工程化为 **package-first**：可校验交接包（HANDOFF.md + manifest@2 + 证据 + trust + 血缘）。能力更强，但"对接提示词"被埋在工具/命令后面，使用抽象。
3. 2026-10-22 文档审计确认：原意未丢失，缺的是"面"（可见入口与工作台）；用户提出 UI 需求，并已选择：输入框左侧「交接」按钮、弹小面板、第一版含生成 + 载入。
4. 原 ROADMAP P2 是"团队/界面"（client 伴侣包 + Agent Teams + 漂移监视 + 自动快照），与"先把对接提示词做成第一入口"的优先级不一致，需要显式修订。

## 决策

### A. 产品叙事

1. **prompt-first**：默认交付物是"新会话可直接照做的对接提示词"（开场提示词）；
2. **package-backed**：交接包、证据、trust 判定、血缘是支撑与可展开项，不是第一入口；
3. 不推翻 P0/P1 的能力、API、证据模型与验收结论；本 ADR 只改变"人怎么进入和使用"。

### B. P2 重排（对 ROADMAP 的修订依据）

1. **P2 首块 = UI 工作台**（client 伴侣包）；
2. Agent Teams 交接、漂移监视、定时/自动快照**后移**（P2 后段或 P3），另行评审，不在 UI v1 范围；
3. P2 门槛改为：浏览器实测 UI 闭环 + `docs:check` 0 error + 既有单测回归（数量以测试输出为准）。

### C. UI 交互（用户已确认）

1. 入口：对话输入框左侧「交接」按钮（宿主槽位 `conversation.input.left` 已核实可注册）；
2. 点击：弹小面板——标题预填、备注可选；
3. 面板含两个动作：**生成**（显示 batchId、目录、warnings，并提供"复制新会话开场提示词"）与**载入**（列最近批次 → 选择 → 显示 trust/drift → 把指针或开场提示词填回输入框）；
4. 工作台页复用同一数据与动作（批次列表、状态徽章、详情、校验、继续交接、打开目录/复制路径）。

### D. 技术形态与边界

1. 同一插件包新增 **Client half**；通过 `host.call` 调本包宿主 RPC → 现有 handoff service；
2. UI **不做业务逻辑**：不复制 manifest 解析/校验规则，不直接读文件系统；
3. v1 不引入网络/子进程/LLM；写操作（生成/append/update）必须由用户点击触发并显示目标目录；
4. P0/P1 工具 API 与证据模型不变；不修改历史批次。

### E. 交付判定

浏览器实测"UI 生成 → 复制开场提示词 → 新会话载入 trust"闭环；工作台列表/详情/错误提示可用；
`docs:check` 0 error；既有单测全绿；验收记录写入 `docs/handoff-kit/acceptance/P2.md`（D5 产出）。

## 后果

**正面**：用户原意重新成为第一入口；包与证据仍在底层；P2 目标单一、可验收。

**代价**：需维护 Client half 构建与刷新流程；宿主 RPC 注册方式与 client 打包方式在实现首日需先验证（`host.call` 通道已核实，注册 API 未核实）；浏览器验收需人工点击。

## 未采纳

| 方案 | 否决理由 |
|---|---|
| 只加一个按钮、不做工作台 | 插件能力多，但没有"看/管"界面；用户要的是可感知的入口 |
| UI 自行读文件系统 / 自行解析 manifest | 违反单一事实来源，制造第二套校验逻辑 |
| 把 UI 塞回 P1（已完成范围） | 破坏 P1 冻结与验收边界；应作为 P2 演进 |
| 先做 Agent Teams/自动化 | 与用户当前痛点（使用抽象、原意未体现）无关；且任务板有 G12 外部缺陷 |
| 改变 P0/P1 的证据/trust 模型 | 现有模型已被验收，UI 只需展示 |

## 生效

自 2026-10-22 起生效；P2 的计划、ROADMAP 修订、新会话入口均以本 ADR 为依据。后续变更写新 ADR，不改本文件。
